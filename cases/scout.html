SCOUT

Agentic commerce flight booking prototype

What it is

An exploration of what flight discovery and booking could become when the interface is a conversation and AI agents can increasingly act on our behalf.

The problem

Flight search today is form-first: filters, grids and comparison tables. SCOUT asks what the experience looks like when discovery is conversational instead — and how to evolve the interface without breaking the working prototype underneath it.

Approach

I kept the existing backend (server/atlas.js) untouched and built a parallel React/Vite UI layer alongside it, so the working prototype stayed the source of truth while I validated the new architecture safely.

The UI is built on unstyled primitives — Thread, Composer and Message — so SCOUT keeps its own visual treatment while the library handles chat state, scrolling, keyboard behaviour and cancellation. The current treatment is "Expandable Glass": the first message expands the chat panel and lifts the hero copy. Most of the recent iteration has been visual — a seamless destination background loop, hero positioning, and many small passes on chatbox opacity.

Tech

  • Node backend (server/atlas.js) kept as the working prototype’s source of truth
  • React + Vite UI layer on @assistant-ui/react 0.15.15, with the Vite dev proxy forwarding /api to the backend on port 3000
